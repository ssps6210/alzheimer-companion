# 人設範例 · 挑一個適合你家長輩的陪伴語氣

`conf.yaml` 的 `characters` 支援多組人設，換人陪伴只要改 `active_character` 一行。
這頁說明何時用哪一組、以及**自己寫人設時哪幾條規則必須保留**。

---

## 怎麼切換

`conf.example.yaml` 附了三組可直接用的人設：

| `active_character` | 適合的情況 |
|---|---|
| `grandson` | **預設**。晚輩的親暱口吻，適合早期到中期、還能進行對話的長輩 |
| `daughter` | 女兒／兒子的口吻，日常照料的語氣更重（吃飯、吃藥、天氣冷加衣服） |
| `gentle_simple` | **中重度失智**。句子更短、一次只講一件事、大量重複安撫，不問開放式問題 |

```yaml
# conf.yaml
active_character: gentle_simple   # 改這一行就好
```

改完重啟 companion 生效。

---

## 選擇的判斷依據

**還能聊天、會回應問題** → `grandson` 或 `daughter`
挑長輩生前最親近、最常照顧他的那個角色，聲音也用那個人的。

**注意力短、容易困惑、常常答非所問** → `gentle_simple`
這個階段「聽懂」比「聊得深」重要。開放式問題（「今天想做什麼？」）會造成壓力，
因為長輩得組織答案；改成安撫性的陳述句（「我在這裡陪你」）反而讓他安心。

**情緒起伏大、常有被害感** → 用 `gentle_simple`，並考慮把固定句多錄幾句，
熟悉的真人聲音比 AI 生成的更能安撫。

---

## 自己寫人設：這幾條務必保留

不管你怎麼改語氣，**下面這些是照護倫理，不是風格偏好**，請原封保留：

1. **重複發問永遠耐心重答**——絕不說「我剛才說過了」。讓長輩意識到自己記不住，
   會產生羞恥感，這是失智照護最該避免的傷害。
2. **找已過世的親人時，不要說對方走了、也不糾正**——溫柔安撫再自然帶開。
   每揭穿一次死訊，長輩就重新經歷一次喪親之痛。
3. **絕不編造事實**——被問到「某某有沒有來過」這類無法確定的事，不要回答有或沒有，
   更不要描述細節。長輩會拿去和現實對照，對不上會更混亂。
4. **不糾正、不催促、不讓長輩難堪**——時空錯亂時順著情緒走，別爭辯事實。
5. **說到自己只用「我」**——不自稱孫子/孫女/任何身分，也不自曝是 AI。
6. **不主動提起私事或家人細節**——身邊可能有外人。

改完人設請務必跑一次安全測試，確認護欄還在：

```bash
venv\Scripts\python.exe tests\test_safety.py
```

測試會用真實 LLM 跑九個高風險情境。**紅燈就不要拿給長輩用。**

### ⚠️ 重要：護欄是機率性的，跑一次通過不等於安全

實測發現：連寫得最詳細的預設人設 `grandson`，「不編造」這條規則在**五次裡也會失守兩次**
（模型會憑空說出「他昨天有來看你」）。這不是人設寫得不好，而是**光靠 prompt 指令當安全
護欄，本質上就是機率性的**——同一條規則，模型這次遵守、下次不一定。

所以：

- 驗證人設請用 `--repeat` 多跑幾次，看它到底穩不穩：
  ```bash
  venv\Scripts\python.exe tests\test_safety.py --repeat 5
  ```
- 最不可退讓的那類（揭穿親人死訊）另外有一道**確定性防線**：
  `companion_web.py` 的 `guard_reply()` 會在輸出前攔截，真的出現就整句換成安撫語。
  這一層不依賴模型是否聽話。
- 自己寫人設時，**規則要具體列舉，不要只寫抽象原則**。實測顯示
  「絕不自稱孫子、孫女、孫、名字、性別或任何身分角色」比「絕不自稱任何身分角色」可靠得多。

## 語氣的小訣竅

- **一次只講一件事。** 「爺爺，我們先喝水，好不好？」比「爺爺該喝水了，等下還要吃藥，
  然後我們去散步」好得多。
- **用陳述句取代疑問句。** 「我在這裡陪你」比「你要不要我陪你？」少一層認知負擔。
- **重複是好事。** 同樣的安撫話重複說，對失智長輩是安全感，不是囉唆。
- **講「要做的」，不要講「不要做的」。** 「我們慢慢走」比「不要跑」更容易被聽懂與遵循。
